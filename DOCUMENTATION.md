# Pulse Accounting System - Comprehensive Developer Guide

## 1. Introduction
Pulse is a robust, multi-currency accounting system designed for small to medium businesses. It allows users to track financial accounts, manage transactions in multiple currencies (BDT/USD), handle billing/invoicing, and generate detailed financial reports.

**Target Audience:** Beginner to Intermediate Developers.

---

## 2. Technology Stack used
*   **Frontend**: React.js (Vite), Bootstrap 5 for UI, Axios for API calls.
*   **Backend**: Node.js with Express.js framework.
*   **Database**: MongoDB (using Mongoose ODM).
*   **Authentication**: JWT (JSON Web Tokens).

---

## 3. Project Structure
The project is divided into two main folders:

### **A. Backend (`/backend`)**
This is the "server" that handles data logic and connects to the database.
*   `src/index.js`: **Entry Point**. Starts the server and connects to the database.
*   `src/models/`: **Database Schemas**. Defines what data looks like (e.g., a Transaction has an amount, date, and description).
*   `src/controllers/`: **Business Logic**.
    *   `transactionController.js`: Handles creating transactions, calculating balances, and generating statements.
    *   `authController.js`: Handles login and user registration.
*   `src/routes/`: **API Endpoints**. Defines URLs like `/api/login` or `/api/transactions`.
*   `src/middleware/`: **Security**. Checks if a user is logged in (`auth.js`) before allowing access.

### **B. Frontend (`/frontend`)**
This is the "client" or the visible website that users interact with.
*   `src/pages/`: **Screens**. Contains full pages like `Dashboard.jsx`, `Ledger.jsx`, `Login.jsx`.
*   `src/components/`: **Building Blocks**. Reusable parts like `Sidebar.jsx` (navigation) or `Layout.jsx` (page frame).
*   `src/context/`: **Global Data**. Stores the current logged-in user's info so it's accessible everywhere.
*   `src/api/axios.js`: **Network Tool**. A configured tool to make requests to the backend.

## 4. Setup Guide (How to Run)

### **Prerequisites**
1.  Install **Node.js**: [Download Here](https://nodejs.org/)
2.  Install **MongoDB**: [Download Community Server](https://www.mongodb.com/try/download/community) and install **MongoDB Compass** (a visual tool to see your data).

### **Step 1: Start the Database**
Ensure MongoDB is running (it usually starts automatically after installation).

### **Step 2: Start the Backend (Server)**
1.  Open a terminal (Command Prompt or PowerShell).
2.  Navigate to the backend folder: `cd backend`
3.  Install dependencies (only needed first time): `npm install`
4.  Start the server: `npm start`
    *   *You should see: "Server is running on port 5000" and "MongoDB connection established."*

### **Step 3: Start the Frontend (Client)**
1.  Open a **new** terminal window.
2.  Navigate to the frontend folder: `cd frontend`
3.  Install dependencies (only needed first time): `npm install`
4.  Start the app: `npm run dev`
    *   *You will see a local URL, usually `http://localhost:5173`.*
5.  Open that URL in your browser.

**Default Login:**
*   Username: `admin`
*   Password: `admin123`

## 5. Key Features & How They Work (Code Walkthrough)

### **A. Transaction Numbering (TRX ID)**
Every transaction gets two numbers:
1.  **Serial Number (`serial_number`)**: A simple integer (1, 2, 3...) used for fast sorting in the database.
2.  **TRX ID (`trx_id`)**: A formatted string (e.g., `TRX001`, `TRX042`) shown to users.

**How it works (`backend/src/models/index.js`):**
When a transaction is saved:
1.  A "Counter" in the database is found and incremented by 1.
2.  The new number is assigned to `serial_number`.
3.  The `trx_id` is generated by padding that number with zeros and adding "TRX".

### **B. Multi-Currency Balance Sync**
The system tracks separate balances for BDT (Bangladeshi Taka) and USD.
**Logic (`backend/src/controllers/transactionController.js`):**
*   **Normal Transactions**: If you credit 100 BDT, the BDT balance increases.
*   **Exchange Transactions**: If you "Buy USD" (Exchange), the system deducts BDT but **adds to the USD balance**.
*   **Re-calculation**: The system can re-calculate balances from scratch by summing up all past transactions to ensure accuracy.

### **C. Account Statement Generation**
The statement logic (`getAccountStatement`) works like this:
1.  Fetch all transactions for an account.
2.  Start with the `Opening Balance`.
3.  Loop through transactions chronologically.
4.  Update the "Running Balance" step-by-step.
5.  *Crucial*: If a transaction is an "Exchange", it updates the target currency's running balance, not the source currency.

## 6. Common Developer Tasks

### **Task: Adding a New Column to the Ledger**
1.  **Frontend**: Open `frontend/src/pages/Ledger.jsx`.
2.  Add a `<th>New Column</th>` in the `<thead>` section.
3.  Add a `<td>{transaction.new_field}</td>` in the `<tbody>` loop.
4.  **Backend** (if needed): Ensure the data is sent in the API response in `transactionController.js`.

### **Task: Modifying an API Endpoint**
1.  Identify the route URL (e.g., `/api/transactions`).
2.  Find the file in `backend/src/routes/api.js`.
3.  See which controller function handles it (e.g., `transactionController.getTransactions`).
4.  Edit that function in `backend/src/controllers/transactionController.js`.

## 7. Troubleshooting

**Error: "429 Too Many Requests"**
*   **Cause**: You refreshed the page too fast.
*   **Fix**: Wait minute or restart the backend server. We increased the limit to 500 requests/15min to prevent this.

**Error: "500 Internal Server Error"**
*   **Cause**: Usually a bug in the code.
*   **Fix**: Check the terminal running the **Backend**. It will print the exact error message.

**Error: "Network Error"**
*   **Cause**: The backend server is not running.
*   **Fix**: Ensure you have a terminal running `npm start` in the `/backend` folder.
